## Возможности

ccemaphore — небольшой плавающий светофор, который держится поверх всех окон (в том числе в
полноэкранном режиме). Он сводит состояние всех ваших чатов Claude Code — из всех окон — к одному
цвету, чтобы не переключаться между окнами только ради проверки статуса.

- **Наведите курсор на светофор** — откроется панель со всеми активными сессиями, сгруппированными по
  состоянию **Ожидают → В работе → Готово**: проект · git-ветка · заголовок чата · % контекста · текущая
  команда. Внизу панели — **Чаты**, **История**, **Настройки** и **Завершить**; **↻** вверху обновляет
  список.
- **Перетащите** светофор в удобное место; переключатель **Закрепить позицию** в Настройках зафиксирует
  его.
- **Чат просит разрешение?** Светофор тут же превращается в **ленту** с кнопками **Разрешить /
  Запретить / Всё в чате** (разрешать в этом чате всё, больше не спрашивая) и самой командой — можно
  ответить, не открывая чат.
- **Чат закончил работу?** Рядом со светофором появляется зелёное уведомление «готово»; по кнопке
  **Перейти в чат** откроется нужная вкладка Cursor (или терминал).
- **Идёт сжатие контекста (compacting)?** На жёлтой лампе появляется значок сжатия — значит, занят, а не
  завис.
- **Два агента, один светофор.** Треды Codex из приложения ChatGPT (или Codex CLI) стоят рядом с чатами
  Claude Code; у каждой строки бейдж агента (Claude / Codex) и значок хоста (приложение Claude, IDE,
  Терминал, приложение ChatGPT). **Перейти в чат** — или клик по строке чата в панели — открывает нужное
  место: вкладку Cursor, сессию в приложении Claude или тред Codex.
- **Субагенты.** Чат, запустивший субагентов (Task-агенты Claude, workflow, дочерние треды Codex),
  получает шеврон — разверните и увидите, чем занят каждый.
- **Группировка по продукту.** Ведёте backend, frontend и лендинг одного продукта параллельно? Выберите
  **По продукту** в **Настройки ▸ Группы продуктов**: вкладка «Чаты» соберёт чаты по папке продукта
  (`продукт › подрепозиторий`), проекты приложения ChatGPT и папки с несколькими репозиториями
  подставляются автоматически.
- **Лимиты Codex.** Окна использования 5 часов / неделя, которые сообщает Codex, внизу вкладки «Чаты».

Всё происходит прямо у светофора — никаких всплывающих уведомлений в углу экрана, которые нужно ловить.

Статистика токенов и расходов по каждой сессии и история по дням берутся из
[`ccusage`](https://github.com/ryoppippi/ccusage), если он установлен — и для Claude Code, и для Codex
(ccusage ≥ 20), с разбивкой и фильтром Claude / Codex в окне «История».

## Языки

ccemaphore полностью переведён на **English, Русский, Español, Deutsch, Français**, причём язык
переключается на лету — без перезапуска. Откройте **Настройки ▸ Язык** и выберите нужный (у каждого —
своё название и флаг), интерфейс тут же обновится. Вариант **Системный** берёт язык из настроек macOS
(если перевода нет — английский).

Этот README тоже есть на всех пяти языках — переключатель вверху страницы.

## Приватность

Всё, что показывает ccemaphore, вычисляется на вашем Mac по локальным файлам — в основном `~/.claude` и
`~/.codex`. Содержимое переписки нигде не сохраняется и никуда не отправляется. Папка `~/.claude` скрытая
(не относится к защищённым TCC-каталогам), поэтому macOS не спрашивает доступ к ней. Никакой телеметрии
и аналитики.

В сеть уходит только следующее:

- **Проверка обновлений → GitHub.** Если обновления не выключены, ccemaphore раз в сутки спрашивает у
  GitHub, нет ли новой версии, и скачивает её оттуда же. GitHub видит ваш IP-адрес, версию приложения
  (в User-Agent, например `ccemaphore/1.3.0 Sparkle/2.10.0`) и предпочитаемый язык (заголовок
  `Accept-Language`, который добавляет macOS). Каждая проверка ещё и увеличивает публичный счётчик
  скачиваний файла `appcast.xml` в релизе — одно общее число, которое видно всем и по которому вас не
  опознать. Cookies не сохраняются, сведения о системе не отправляются.
- **Решаете вы.** При первом запуске панель спрашивает, как обновляться: автоматически, только
  сообщать или не проверять, — и до ответа автоматических проверок нет. Поменять выбор можно в любой
  момент в **Настройки ▸ Обновления**; с выключенными обновлениями ccemaphore сам не проверяет никогда
  (проверить вручную по-прежнему можно).
- **ccusage** (статистика токенов и расходов, только если установлен Node или Bun) запускается через
  `bunx`/`npx` — они могут скачать пакет из реестра npm, а сам ccusage может загрузить актуальные цены
  моделей.
- **Удалённые хосты по SSH** (по желанию) — ccemaphore подключается только к хостам, которые вы добавили
  сами, через ваш `ssh`.

Больше ничего: ни содержимое чатов, ни какие-либо идентификаторы не покидают ваш Mac. Если у вас
исходящий файрвол (Little Snitch, LuLu), при первой проверке обновлений он один раз спросит про GitHub.

## Как это работает

ccemaphore определяет состояние сессий по локальным файлам и для каждого агента сводит вместе несколько
источников.

### Claude Code — реестр сессий (основной источник, настройка не нужна)

Claude Code 2.1.29x и новее сам публикует состояние каждой запущенной сессии в
`~/.claude/sessions/<pid>.json`: работает / простаивает / ждёт (и чего именно — ответа на запрос
разрешения или вашего ответа), имя сессии, где она запущена (десктопное приложение, IDE, терминал) и
папку запуска. ccemaphore считает этот сигнал самым точным и применяет его поверх косвенных источников
ниже. Это слово самого Claude Code, поэтому хуки для него не нужны.

### Режим A — наблюдение за файлами (всегда включён, настройка не нужна)

Через FSEvents он наблюдает за `~/.claude/projects/**/*.jsonl` (транскрипты, которые Claude Code пишет
в реальном времени) и определяет состояние каждой сессии по концу её файла:

- **работает** — последняя запись свежая и относится к незавершённому ходу (`tool_use` ассистента,
  незакрытый стрим, только что пришедший `tool_result`, новый промпт или повтор после `api_error`).
- **готово** — ход завершился штатно (`stop_reason: end_turn`).
- **ждёт** — по возможности: активности давно не было, но сессия ещё жива, а файл обрывается на непарном
  `tool_use`.

Транскрипты суб-агентов приписываются к родительской сессии — пока работает суб-агент, родитель тоже
считается работающим. Активность определяется по последнему реальному `timestamp`, **а не** по mtime
файла: правки метаданных (заголовок, последний промпт) сдвигают mtime уже после того, как чат затих.

### Режим B — хуки (по желанию, в один клик)

Включите **«Точное определение статуса»** в Настройках, и ccemaphore установит хуки Claude Code для:

- **точного определения `done` / `waiting`** — надёжнее, чем чтение конца транскрипта;
- **интерактивной ленты разрешений** (та самая лента из трёх кнопок **Разрешить / Запретить / Всё в
  чате** выше);
- **доверенных команд** — списка команд, которые одобряются автоматически, чтобы лента для них не
  появлялась (совпадение по подстроке команды).

Хуки добавляются в `~/.claude/settings.json` аккуратным слиянием (повторная установка ничего не ломает)
и полностью обратимы.

### Codex (приложение ChatGPT) — наблюдение за файлами + хуки по желанию

Если существует `~/.codex`, ccemaphore следит и за Codex: транскрипты тредов
(`~/.codex/sessions/**/rollout-*.jsonl` — `task_started` / `task_complete` / `turn_aborted` дают
«работает / готово»), каталог тредов (`state_5.sqlite`, открывается только на чтение — заголовки, папки,
проекты, архив) и блокировки записи тредов (их держит приложение ChatGPT, пока тред открыт). Запросы
подтверждения Codex в транскрипт не пишет, поэтому «нужны вы» для Codex даёт только режим хуков:
**Точный статус через хуки Codex** записывает хуки ccemaphore в `~/.codex/hooks.json`, а отдельный
переключатель **Запросы разрешений Codex** превращает запрос подтверждения в красный свет + ленту
(доверенные команды разрешаются автоматически). Codex запускает только хуки, которым **доверяет**: после
установки один раз одобрите `hooks.json` в приложении ChatGPT (настройки Codex → Hooks) или командой
`/hooks` в Codex CLI — строка в Настройках покажет, доверены ли хуки. Тред, который приложение ChatGPT
*импортировало* из Claude Code, сохраняет бейдж Claude; чистое зеркало без ходов Codex скрывается, чтобы
ничего не дублировалось.

## Установка

1. [**Скачайте последний `.dmg`**](https://github.com/hakkazuu/ccemaphore/releases/latest) — он подписан
   и нотаризован, поэтому Gatekeeper открывает его без предупреждений.
2. Откройте DMG и перетащите **ccemaphore** в **Applications**.
3. Запустите. ccemaphore работает в фоне, без меню и без иконки в Dock — только плавающий светофор.

### Настройка при первом запуске (по желанию, но рекомендуется)

- **Разрешите Универсальный доступ (Accessibility)** (Системные настройки ▸ Конфиденциальность и
  безопасность ▸ Универсальный доступ: включите ccemaphore, а если его нет в списке — добавьте кнопкой
  **+**; само приложение этот доступ не запрашивает). Он нужен только при переходе в чат: убедиться, что
  впереди нужное окно Cursor, прежде чем открыть вкладку чата, и поднять уже открытое окно VS Code
  Remote-SSH вместо того, чтобы открывать новое.
- **Выберите, как ccemaphore будет обновляться** — панель спросит один раз: автоматически, только
  сообщать или не проверять ([подробнее ↓](#обновления)).
- **Включите «Точное определение статуса»** в Настройках — это активирует режим B (хуки + лента
  разрешений).
- **Используете Codex в приложении ChatGPT?** Он подхватывается автоматически. Чтобы «готово» и «нужны
  вы» появлялись мгновенно, включите **Точный статус через хуки Codex** (и **Запросы разрешений Codex**),
  затем один раз одобрите хуки в настройках Codex приложения ChatGPT — строка покажет, когда им доверяют.
- **Оба приложения уведомляют и сами.** Если светофора достаточно, выключите уведомления приложения
  Claude / ChatGPT в Системных настройках ▸ Уведомления или в настройках уведомлений самих приложений.
- **Для статистики токенов и расходов** нужен Node или Bun в `PATH` — ccemaphore запускает
  [`ccusage`](https://github.com/ryoppippi/ccusage) через `bunx`/`npx`. Без него история всё равно
  работает, просто без цифр по токенам.
- **Если при клике по уведомлению у светофора перемешиваются рабочие столы** — это делает macOS, а не
  ccemaphore: настройка «Менять расположение рабочих пространств Spaces в зависимости от недавнего
  использования» (Системные настройки ▸ Рабочий стол и Dock ▸ Mission Control). Выключите её или выполните
  `defaults write com.apple.dock mru-spaces -bool false && killall Dock` — порядок столов перестанет
  меняться, а переход к нужному окну продолжит работать.

### Обновления

ccemaphore обновляется сам — с помощью [Sparkle](https://sparkle-project.org):

- **Три режима** — выбираются один раз при первом запуске и меняются в **Настройки ▸ Обновления** (там же
  видны ваша версия и время последней проверки):
  - **Автоматически** — раз в сутки проверяет и скачивает в фоне; когда новая версия готова, один клик
    **Перезапустить** ставит её и перезапускает приложение. Обычный выход из приложения тоже её
    устанавливает. Если ваша учётная запись не может заменить приложение там, где оно лежит (нет прав
    на запись или его установила другая учётная запись), скачанное обновление вместо этого ждёт клика
    **Установить** и пароля администратора — при выходе оно не ставится.
  - **Только сообщать** — раз в сутки проверяет и сообщает; один клик **Обновить** скачивает,
    устанавливает и перезапускает.
  - **Выкл.** — сам не проверяет никогда; проверить вручную по-прежнему можно.
- **Подписано и проверено.** Обновление — тот же подписанный и нотаризованный DMG, что и на странице
  релизов, и прежде чем что-то распаковать, ccemaphore проверяет его подпись EdDSA — и подпись самого
  фида обновлений (`appcast.xml`).
- **Всё в панели**, на языке приложения. Вне её всё же может появиться маленькое окно установщика Sparkle
  с прогрессом, если установка затянулась; запрос пароля администратора macOS — только если ваша
  учётная запись не может заменить приложение там, где оно лежит (текст запроса от Sparkle, на
  английском); а на macOS 13–14.3 — окно Gatekeeper «Проверка…» при первом запуске обновлённого
  приложения.
- **Не посреди запроса разрешения.** Пока у светофора ждёт ответа запрос разрешения, **Перезапустить**,
  **Обновить** и **Установить** тоже ждут — выход из приложения никогда не обрывает хук разрешений агента.
- **Держите приложение в обычной папке.** Если запустить ccemaphore прямо из DMG (или macOS запустит его
  из временного места — так называемая App Translocation), обновиться он не сможет: панель попросит
  перенести его в «Программы» (Applications).
- **Обновляетесь с 1.2.x или более ранней версии?** В них обновлятора нет: один раз скачайте 1.3.0 и
  перетащите поверх старой копии — дальше ccemaphore обновляется сам. 1.3.0 подписан новой командой
  разработчика, поэтому Универсальный доступ, выданный старой версии, перестаёт действовать, хотя
  Системные настройки ▸ Конфиденциальность и безопасность ▸ Универсальный доступ могут по-прежнему
  показывать ccemaphore включённым. Удалите его там (**−**) и добавьте заново (**+**) или выключите и
  снова включите.

## Участие в разработке и сборка из исходников

Нужны **macOS 13+** и **Xcode 26**. Проект хранится как готовый Xcode-проект (не SwiftPM), так что
`swift build` не сработает — откройте его в Xcode и нажмите ⌘R (появится плавающий светофор, иконки в
Dock нет):

```sh
open ccemaphore.xcodeproj
```

Собрать локальный (неподписанный) `.app` для быстрой проверки — Release-сборка через `xcodebuild`, результат
в `build/ccemaphore.app`:

```sh
Scripts/package_app.sh
```

Такая сборка запускается как есть. Не переподписывайте её ad hoc с `--options runtime`: Hardened Runtime
тогда откажется загружать встроенный фреймворк Sparkle, и приложение упадёт при запуске.

Сборки, которые вы делаете сами (⌘R, `package_app.sh`), никогда не обновляются сами — это умеют только
релизы, подписанные Developer ID. Единственная зависимость, [Sparkle](https://sparkle-project.org),
подключена как Swift-пакет, закреплённый на версии 2.10.0; Xcode скачает её при первом открытии проекта.

App Sandbox выключен (иначе не прочитать `~/.claude`), поэтому распространение — мимо Mac App Store.
Issue и pull request приветствуются. Подписанные релизы собирает мейнтейнер через GitHub Actions —
см. [`docs/RELEASING.md`](docs/RELEASING.md).
